# Pilot tests

Each pilot item has tests that prove its "Done when" check from the Pilot Readiness Brief.

| File | What it tests | How to run |
|---|---|---|
| `item1.test.js` | Item 1 database rules: regions, schools, classes, roles, enrolment and security, on a local Postgres (PGlite) loaded with `bootstrap.sql` (a stand-in for the live schema) and the real migration | `npm i @electric-sql/pglite@0.2.17 && node item1.test.js` |
| `pilot-admin.test.ts` | The `pilot-admin` Edge Function (new basic-phone learner accounts) against a stand-in for Supabase | start `pilot-admin.mock.ts` (port 9997) and the function with `SUPABASE_URL=http://localhost:9997`, then `deno run -A pilot-admin.test.ts` |
| `item2.test.js` | Item 2 consent rules: both consents needed, withdrawal takes effect at once, data flagged for removal, no way around the rules | `node item2.test.js` |
| `item2.ui.test.js` | Consent screens end to end: school letter, parent form upload, withdrawal, data removal | as for `item1.ui.test.js` |
| `item7.test.js` | Item 7 message gate: consent, pause, allowed hours (Namibian time), weekly and text limits, content result, every attempt logged, review sample, rule changes, security | `node item7.test.js` |
| `agent-messenger.rules.test.ts` | Fixed content rules (links, phone numbers, unsuitable words, length) | `deno run -A agent-messenger.rules.test.ts` |
| `agent-messenger.test.ts` | The agent-messenger Edge Function end to end: only the server can send, AI review fails closed, delivery | start `agent-messenger.mock.ts` (port 9995) and the function with `SUPABASE_URL=http://localhost:9995 ANTHROPIC_URL=http://localhost:9995/v1/messages`, then `deno run -A agent-messenger.test.ts` |
| `item7.ui.test.js` | Message review screens and the learner's agent messages | as for `item1.ui.test.js` |
| `item5.test.js` | Item 5 pause: who may pause or resume, a paused learner gets nothing (including messages prepared before), the log shows who paused, full history | `node item5.test.js` |
| `item5.ui.test.js` | Pause and resume from the teacher's class list | as for `item1.ui.test.js` |
| `../signout.ui.test.js` | Sign out removes the session from the phone and cancels it on the server | as for `item1.ui.test.js` |
| `item4.test.js` | Item 4: learning record (consent first, no duplicates, bad records ignored) and three Mondays of summaries with exact figures, logged without names, withdrawal | `node item4.test.js` |
| `item4.ui.test.js` | Activity from the real chat box, offline then synced once, nothing for unconsented learners, sign-out clears the queue, the teacher's summary card | as for `item1.ui.test.js` |
| `item3.test.js` | Item 3 tests: answers never leave the server, drafts must be approved, consent and grade first, two sittings, fair marking, a full class of 30 (20 on phones, 10 on paper), every score in one place with pilot IDs only, closing times, withdrawal. Set `K12_TEST_BANK` to the generated `seed.sql` to also check the real question bank (kept out of this public repository) | `node item3.test.js` |
| `aim-lock.test.ts` | The agent's pilot features: it stays quiet while a pilot learner sits a test (nobody else is affected, and an error never locks anyone out), and it keeps pilot learners' questions and replies for review, stored by the server only | start `aim-lock.mock.ts` (port 9994) and the `aim` function with `SUPABASE_URL=http://localhost:9994 SUPABASE_ANON_KEY=anon SUPABASE_SERVICE_ROLE_KEY=svc ANTHROPIC_API_KEY=dummy ANTHROPIC_URL=http://localhost:9994/v1/messages`, then `deno run -A aim-lock.test.ts` |
| `item3.ui.test.js` | Test screens end to end: approval and dates, sitting the test on a 390 px phone with and without signal, the agent lock, printing the paper version, entering paper answers, the score list and CSV | as for `item1.ui.test.js` |
| `item8.test.js` | Item 8: the one-step monthly report for 28 schools in 14 regions, every figure checked against a separate count (school, region, rural and urban, class, whole pilot), sessions rule, weekly figures, champions see their region only, prices, the data-spend alert (fires, does not repeat, early-month floor), data records from the phone, withdrawal | `node item8.test.js` |
| `item8.ui.test.js` | Report screens end to end: the alert, last month's report in one click, the CSV, prices and typed-in costs, the champion's region report, and data use measured on a learner's phone | as for `item1.ui.test.js` |
| `item9.test.js` | Item 9: replies kept only for pilot learners with consent and only by the server, the monthly random sample (10 per teacher, own classes only, one a month), reviewing with three verdicts and comments, time recorded, results for the team without learner names, withdrawal | `node item9.test.js` |
| `item9.ui.test.js` | Review end to end: a chat reply kept for review, samples prepared, a teacher reviewing ten answers on a 390 px phone (timed), results by verdict, the CSV | as for `item1.ui.test.js` |
| `item10.test.js` | Item 10: every column of every file is in the data dictionary and nothing else is; no names, phone numbers, K12Plus IDs, emails, account IDs, school names, class join codes or free text; small groups hidden (every described group has at least 5 learners); weeks not times; school codes stable and their key admin-only; figures checked; withdrawal | `node item10.test.js` |
| `item10.ui.test.js` | The export downloaded from the Pilot page, opened with Python's zipfile (valid, eight files, README, dictionary, Excel-friendly CSV), and the private school code key | as for `item1.ui.test.js` |
| `item15.ui.test.js` | Item 15: every public page and the app say "agent" and "learners" (what a visitor sees, plus a scan of messages shown later), the four agent names with STEM first, Grades 8-12 on the homepage and USSD screen, the reworded promises, no small uppercase titles, and the backend named AI Math Agent | as for `item1.ui.test.js` |
| `item11.test.js` | Item 11 end to end: the real `ussd` Edge Function in Deno, answering gateway requests in the Africa's Talking format, against PGlite with all the migrations (through a local stand-in for Supabase, the website and the Claude API). Every code, practice, lessons, the agent, results, shared phones, unknown numbers, consent, the test lock, the daily limit, joining a class, the simulator, screen length and characters, and that no phone number is stored | `node item11.test.js` (needs deno) |
| `item11.ui.test.js` | Item 11: the USSD simulator on the administrator's Pilot page, through the real function | as for `item1.ui.test.js`, and needs deno |
| `item12.test.js` | Item 12 in the database: quiz results sent again after a dropped signal are stored once, older results are untouched, and only pilot teachers, champions and administrators can release a lesson pack to learners (a check belongs to one version of a pack) | as for `item1.test.js` |
| `item12.ui.test.js` | Item 12 end to end: teachers check lessons; a learner saves one, works through all of it with the network off (marking, hints, solutions, study recommendation), finishes a quiz and asks the agent a question; when the signal returns, with the first replies lost and two tabs reconnecting at once, the server holds exactly 1 lesson record, 12 practice records, 1 quiz result and 1 agent question. Also a learner outside the pilot (nothing recorded), phone width and before logging in | as for `item1.ui.test.js` |
| `item13.test.js` | Item 13: data use. Runs `item13.measure.js` (the real site in Chromium with its service worker, behind an HTTPS and HTTP/2 stand-in for k12plus.app, unpkg, Google Fonts and Supabase, counting bytes on the raw connections) and checks first visit, return visit, questions, photos, offline start and the phone's own data counter. Report: `docs/pilot/item13-data-use.md` | `sh item13-tls.sh <folder>` once (needs openssl and certutil), then `TLS_DIR=<folder> node item13.test.js` as root (it listens on port 443) |
| `item1.ui.test.js` | The pilot screens in app.html in headless Chromium, with every click running the real SQL in PGlite | serve the site on 127.0.0.1:8765, set `VENDOR_DIR` to a folder with React and Babel in `node_modules`, then `node item1.ui.test.js` |

This folder is not served by the website (`tests/.htaccess`).
